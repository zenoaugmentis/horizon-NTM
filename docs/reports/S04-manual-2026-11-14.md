Пользователь предоставил сообщение остановки в 03:28:53 и выполнил:

Get-Content .\server.properties | Select-String '^(server-ip|server-port|online-mode|motd)='

Получены исходные четыре значения из начала отчёта. Восстановление

не сравнивались. После восстановления сервер был остановлен; позднее запущен для проверки
отказов, описанной ниже. Последующая остановка не показана.

## 5. Отказы на несовместимую версию

После восстановления настроек пользователь повторно запустил сервер и
выполнил `py "$env:USERPROFILE\s04_reject.py"`. Импорт исторического
s04_status сначала повторил status/ping; он снова завершился PASS.
В отдельных соединениях отправлялся только Handshake с nextState=2,
без Login Start. Результат:

```text
VERSION REJECTION PROBE: protocol=4
TX id=0x00 frame=0f 00 04 09 31 32 37 2e 30 2e 30 2e 31 63 dd 02
RX id=0x00 body_length=38
DISCONNECT: "Outdated client! Please use 1.7.10"
PASS: protocol 4 rejected

VERSION REJECTION PROBE: protocol=6
TX id=0x00 frame=0f 00 06 09 31 32 37 2e 30 2e 30 2e 31 63 dd 02
RX id=0x00 body_length=45
DISCONNECT: "Outdated server! I'm still on 1.7.10"
PASS: protocol 6 rejected
```

Оба JSON reason декодированы как строки, не объекты. Проверены ID и
отсутствие остатка payload. Исходное представление JSON не выводилось:
экранирование и побайтовое содержимое ответов не установлены. Измеренные
38/45 байт не являются универсальными длинами Disconnect.

## 6. Повторяемый инструмент из комплекта

Из корня репозитория:

```powershell
py tools/probe_s04.py status
py tools/probe_s04.py online
py tools/probe_s04.py reject
```

Последняя команда ожидает online-mode=true. После отдельной подготовки
локального offline-сервера:

```powershell
py tools/probe_s04.py offline
```

Синтетические проверки инструмента:

```powershell
py -m unittest discover -s tests -p 'test_s04_*.py' -v
```

Новый инструмент объединяет прежние зонды и убирает сетевые побочные
эффекты импорта. Его проверки не заменяют исторические игровые опыты.
Результаты локального запуска тестов см. README комплекта.

## Ограничения

Нет текущего upstream SHA, проверки совместимости Horizon 26.3, запуска
Rust-кода, CI или code review. На сервере нет тестов повреждённых длин, Unicode, legacy ping,
encrypted transport, Forge или полного play. Отказы на версии 4/6 проверены.
Синтетические отрицательные случаи проверяют новый зонд, а не сервер Mojang.
Исходные JAR, миры, персональные журналы и ключевой материал не публикуются.

## 7. Недоступная online-проверка и локальная криптографическая модель

Пользователь подтвердил отсутствие авторизованного лицензионного клиента;
успешный online-вход на текущем стенде проверить нельзя. Не запрашивались
токены и не подменялась авторизация. Это обоснование невозможности
испытания в соответствии с критерием S04.

Контракт online-ветки описан по закреплённым исходникам независимой
реализации в protocol-5-encryption.md. Локальная синтетическая модель
проверяет RSA/Short-массивы, signed hash и AES-CFB8 после открытого
Encryption Response, включая два последовательных пакета и фрагментацию.
Нет запросов к session service, реальных credentials или соединения с
игровым сервером. Это отдельный уровень доказательств.
