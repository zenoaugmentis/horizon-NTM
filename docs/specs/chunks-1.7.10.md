# S03 · Чанки Minecraft 1.7.10: region, NBT, секции, свет, биомы

Статус: спецификация S03 (#16). Зависит от S01 (`docs/specs/versions.md`), использует
контракт блоков S02 (`docs/contracts/blocks.md`). Дата: 2026-11-08.
Потребители: S06 (эталонные миры), W03, W04, W05, W07, W10, W11, W12, R05, R06, N05.

Источники фактов (код не переносится):
- независимая реализация эпохи 1.7 — pymclevel из MCEdit (ISC): `infiniteworld.py`, `regionfile.py`;
- Horizon `horizon-rust/horizon@447e9d277d06272196ba66363d5ea8d582581c63`:
  `crates/horizon-world/src/{region,nbt,compression,chunk}.rs` — граница в разделе 8.
Помеченное `ПРОВЕРИТЬ S06` подтверждается фикстурой настоящего мира 1.7.10 (S06);
до этого читатель обязан принимать оба варианта, писатель — делать как указано.

Исполняемый эталон — `tools/anvil_1710.py`; тесты и синтетическая фикстура —
`tests/test_anvil_1710.py`. W04/W05 воспроизводят их в Rust.

## 1. Геометрия

| Параметр | Значение |
|---|---|
| высота мира | 256 (`y = 0..=255`) |
| секция | 16 × 16 × 16, `Y = 0..=15`, секция `Y` покрывает `y = 16·Y .. 16·Y+15` |
| чанк | 16 × 16 столбцов, до 16 секций |
| region | 32 × 32 чанка, файл `r.<rx>.<rz>.mca`, `rx = cx >> 5`, `rz = cz >> 5` (арифметический сдвиг) |
| каталоги | верхний мир `region/`, Незер `DIM-1/region/`, Энд `DIM1/region/`; моды — `DIM<n>/region/` |

Индекс блока в секции: `i = (y & 15) << 8 | z << 4 | x` (порядок массивов `[y][z][x]`).
Индекс столбца: `j = z << 4 | x`.

## 2. Region-файл (`.mca`)

- Сектор — 4096 байт. Сектор 0: 1024 записи смещений по 4 байта big-endian:
  старшие 3 байта — номер сектора начала, младший байт — число секторов. `0` — чанка нет.
  Сектор 1: 1024 метки времени `u32` (секунды). Индекс записи: `(cx & 31) + (cz & 31) · 32`.
- Данные чанка с начала своего сектора: длина `u32` BE (считая байт сжатия),
  1 байт типа сжатия, затем сжатое NBT. Хвост сектора до 4096 заполнен нулями.
- Тип сжатия в 1.7.10: `1` — gzip, `2` — zlib (vanilla пишет `2`). Типы `3`, `4` и флаг
  внешнего файла `128` (`.mcc`) появились в новых версиях: в legacy-мире это ошибка чтения,
  а писатель их не использует.
- Чанк не больше 255 секторов (≈ 1 МиБ); больше — ошибка записи, не обрезка.

## 3. NBT

- Big-endian, корневой тег — Compound с пустым именем.
- Допустимы типы `0..=11` (End … IntArray). **`LongArray` (12) в 1.7.10 нет:**
  встретился при чтении legacy-мира — ошибка; писатель его никогда не создаёт.
- Строки — Java modified UTF-8: длина `u16`, `U+0000` пишется как `C0 80`, символы
  вне BMP — двумя суррогатами по 3 байта. Именно так кодируются ключи FML вида `"\u0001…"` (S02).
- Порядок ключей Compound и тип элементов пустого List (`End` или любой) сохраняются как прочитаны:
  без изменений чанк кодируется обратно **байт в байт**.

## 4. Структура чанка

```
"" (Compound)
└─ Level (Compound)
   ├─ xPos             Int        координата чанка X
   ├─ zPos             Int        координата чанка Z
   ├─ LastUpdate       Long       тик мира последнего сохранения
   ├─ TerrainPopulated Byte       1 — декорации (руды, деревья) уже сгенерированы
   ├─ LightPopulated   Byte       1 — свет рассчитан                 ПРОВЕРИТЬ S06, может отсутствовать
   ├─ V                Byte       версия формата чанка, 1            ПРОВЕРИТЬ S06, может отсутствовать
   ├─ InhabitedTime    Long       тики присутствия игроков (локальная сложность)
   ├─ HeightMap        IntArray[256]
   ├─ Biomes           ByteArray[256]                                может отсутствовать
   ├─ Sections         List<Compound>
   ├─ Entities         List<Compound>   формат — W12/S08
   ├─ TileEntities     List<Compound>   формат — W11/S08/S10
   └─ TileTicks        List<Compound>   может отсутствовать
```

Нет `DataVersion` (появился в 1.9) — это признак legacy-чанка вместе с версией мира
`19133` в `level.dat` (S01). Неизвестные теги в корне и в `Level` (их пишут моды Forge)
**сохраняются без изменений**.

### Секция

| Тег | Тип | Размер | Смысл |
|---|---|---|---|
| `Y` | Byte | — | номер секции `0..=15` |
| `Blocks` | ByteArray | 4096 | младшие 8 бит id блока |
| `Add` | ByteArray | 2048 | старшие 4 бита id, ниббл; **только если** нужен (id > 255) |
| `Data` | ByteArray | 2048 | meta, ниббл |
| `BlockLight` | ByteArray | 2048 | свет от источников `0..=15`, ниббл |
| `SkyLight` | ByteArray | 2048 | свет неба `0..=15`, ниббл |

Нибблы — как в S02: чётный индекс — младшие 4 бита байта. `id = Add << 8 | Blocks`.

- Секции без единого не-air блока обычно не пишутся. Отсутствующая секция читается как
  air, `BlockLight = 0`, `SkyLight = 15` (в мирах без неба — `0`).
- Порядок секций в `Sections` не обязан совпадать с `Y`; дубликат `Y` — ошибка чтения.
- `SkyLight` в мирах без неба (Незер, Энд): читатель принимает и отсутствие, и массив нулей;
  писатель пишет 2048 нулей. ПРОВЕРИТЬ S06.

### HeightMap

`IntArray[256]`, индекс `j = z << 4 | x`. Значение — наименьший `y`, начиная с которого
вверх свет неба проходит без ослабления (на 1 выше верхнего блока, гасящего свет).
Это кэш: при несовпадении после загрузки его пересчитывает W10, а не читатель.

### Biomes

`ByteArray[256]`, индекс `j = z << 4 | x`, значение — id биома как **беззнаковый** байт.
`255` (`-1` как signed) — «ещё не вычислен»: биом берётся из генератора при загрузке.
Отсутствие тега = все `255`. Таблица id биомов 1.7.10 — W07.

### TileTicks

Запланированные обновления блоков: `{i: Int — id блока (S02), x, y, z: Int — мировые
координаты, t: Int — через сколько тиков, p: Int — приоритет}`. В 1.7.10 `i` — число,
не строка (строки — с 1.8). `p` — ПРОВЕРИТЬ S06; отсутствие читается как `0`.

## 5. Правила записи (без потерь)

1. Чанк, который не меняли, пишется обратно **байт в байт** по NBT (сжатие может отличаться).
2. Секция, которая была при чтении, остаётся, даже если стала пустой.
3. Новая секция создаётся, когда в ней ставится не-air блок: `Blocks`/`Data`/`BlockLight` — нули,
   `SkyLight` — 15 (в мире без неба — 0).
4. `Add` пишется, если он был при чтении **или** в секции есть id > 255; иначе не пишется.
5. Изменение блока на уровне хранения **не** пересчитывает свет, `HeightMap`,
   не трогает `TileEntities` и `TileTicks` — это делают W10/W11 (как `chunk.rs` у Horizon).

## 6. Что не входит в S03

`level.dat` и игроки — W06; содержимое `Entities` / `TileEntities` — W11, W12, S08;
таблица биомов — W07; генерация — W08/W09; алгоритм света — W10, R06.

## 7. Фикстура для round-trip

Публичная фикстура — **синтетическая**: её генерирует `tools/anvil_1710.py` из
детерминированного описания, в ней нет данных Mojang. Она покрывает: секции не по порядку,
пропущенную секцию, `Add` (id 1204 из S02), все 16 значений meta и света, `Biomes` с `255`,
`HeightMap`, `TileTicks`, незнакомые теги модов в корне и в `Level`, строку с `\u0000` и
символом вне BMP, пустой List. Тест проверяет:

1. запись в `.mca` и чтение обратно — NBT совпадает байт в байт, для gzip и zlib;
2. декодирование в модель и кодирование обратно — байт в байт;
3. значения блоков, света, биомов и высот в известных точках;
4. изменения по правилам раздела 5, включая появление `Add` и новую секцию;
5. отказ на `LongArray`, на типе сжатия `3`/`4`/`128`, на дубликате `Y`, на неверных размерах.

SHA-256 NBT фикстуры зафиксирован в тесте: любое изменение формата его ломает.
Настоящие миры 1.7.10 проверяются тем же кодом локально в S06, без публикации.

```
python -m unittest discover -s tests -p "test_anvil_1710.py" -v
python tools/anvil_1710.py fixture .local/s03/r.0.0.mca     # записать фикстуру
python tools/anvil_1710.py check ПУТЬ/region/r.0.0.mca         # round-trip настоящего region локально
```

## 8. Граница с Horizon

| Horizon (`447e9d2`) | Для legacy |
|---|---|
| `region.rs`: `RegionFile`, `RegionWriter`, `ChunkRecord` | **переиспользуется**: секторы, смещения, метки времени те же |
| `compression.rs`: gzip, deflate, none, lz4 | разрешены только gzip (1) и deflate/zlib (2) |
| `nbt.rs`: modified UTF-8, `JavaString` (UTF-16 без потерь), `LongArray` | переиспользуется; legacy-читатель отклоняет `LongArray` |
| `chunk.rs`: `ChunkData`, палитры 26.3 (`block_states`, `LongArray`) | **не** используется: нужен отдельный `LegacyChunk` (W04/W05) |
| `paletted.rs`: `PalettedContainer` | в памяти секции legacy-чанка хранят `BlockStateId = id<<4|meta` (S02) |

`LegacyChunk` при чтении превращает `Blocks/Add/Data` в состояния S02 и обратно; свет,
`HeightMap`, `Biomes`, `TileTicks` и всё неизвестное хранятся как есть.
