# S05 · Ресурсы, атласы и модели Minecraft 1.7.10

Задача: [#18](https://github.com/zenoaugmentis/horizon-NTM/issues/18).
Дата: 2026-11-14. Статус: описание для проверки; реализация R01/R02 не выполнена.

## 1. Что проверено

Документ описывает ресурсы Minecraft Java Edition 1.7.10 без Forge. S05 опирается на S01.
Здесь «измерено» означает результаты моих команд и проверок в игре;
«требование» — правило для будущей реализации Horizon, которое ещё нужно реализовать и проверить.
[Ручной отчёт](../reports/S05-manual-2026-11-14.md) содержит результаты и ограничения.

Я повторно проверил SHA-1 клиентского JAR:
`e80d9b3bf5085002218d4be59e668bac718abbc6`, совпадает с [S01](versions.md).
В нём 349 PNG и 7 файлов `.mcmeta` в `textures/blocks/`,
214 PNG и 2 `.mcmeta` в `textures/items/`. В корне нет `pack.mcmeta`.
В `assets/minecraft/models/` и `assets/minecraft/blockstates/` файлов нет.
Это не доказательство отсутствия геометрии: отсутствуют именно современные JSON-ресурсы.

Я проводил проверки на клиенте Minecraft 1.7.10 без Forge. Полный журнал запуска я не сохранял. Выдержки журнала и скриншот окрашивания
травы приложены к ручному отчёту. В журнале также есть обращения к Ely/auth; это нужно учитывать при повторении опытов.

## 2. Имена ресурсов и источники файлов

Имя ресурса состоит из пространства имён (namespace) и относительного пути.
В ZIP пути разделяются символом `/`. В Horizon при отсутствии пространства
имён нужно использовать `minecraft`.
Сохранять точные имена ресурсов 1.7.10, включая множественное число `blocks`/`items`.
Не применять современные переименования `block`/`item` автоматически.

| Логический спрайт | Атлас | Ресурс |
|---|---|---|
| `minecraft:stone` | blocks | `assets/minecraft/textures/blocks/stone.png` |
| `minecraft:apple` | items | `assets/minecraft/textures/items/apple.png` |
| `example:machine_front` | blocks | `assets/example/textures/blocks/machine_front.png` |

Последняя строка — пример для будущей реализации, а не результат проверки игры.
Имя спрайта не обязательно совпадает с именем блока в реестре. Текстура зависит
от грани, значения metadata и слоя отрисовки. Одного числового ID для выбора пути недостаточно.
Блок в инвентаре может использовать спрайты из атласа блоков; наличие ItemBlock не означает
поиск одноимённого файла в `textures/items/` (измерено на камне).

R01 должен получать ресурсы из локальной установки игры и проверять версию.
Клиентский JAR и внешние `assets/indexes`/`assets/objects` — разные источники;
В этой работе я исследовал JAR. Полноту внешнего индекса не проверял.
Текстуры интерфейса, сущностей, шрифтов и другие ресурсы могут загружаться отдельно
от атласов блоков и предметов. Поддержку модовых пространств имён и загрузчиков
нужно добавлять отдельно: чтение ресурсов само по себе не даёт совместимости с Forge.

## 3. Ресурс-пак и приоритет

Минимальный ZIP содержит `pack.mcmeta` непосредственно в корне:

```json
{"pack":{"pack_format":1,"description":"Horizon S05 original texture probe v1"}}
```

Вложенная папка перед `pack.mcmeta` не входит в формат тестового пакета.
PNG размещаются под `assets/<namespace>/textures/…`; метаданные анимации —
рядом с PNG, с именем `<name>.png.mcmeta`. Корневой `pack.mcmeta` описывает пак,
а соседний с PNG файл `.mcmeta` — свойства конкретной текстуры. Отсутствие корневого файла в базовом JAR
не означает, что его можно опускать в пользовательском ZIP.

Измерено: собственный ZIP с `pack_format=1` принят клиентом, обе подмены работают.
Другие значения format не подтверждены. В журнале стека есть предупреждения
чтения корневого pack.mcmeta; причина и воспроизводимый результат не установлены.

Требования Horizon: стек состоит из базовых ресурсов и выбранных паков с явным
приоритетом. Для одного пути выбирается старший доступный ресурс. Если пути нет,
поиск продолжается ниже; выбор между несколькими пользовательскими паками
должен давать однозначный результат; выбранный источник нужно указывать в журнале. Зафиксированы перезагрузки A+B, B+A и A+C. Логи сами по себе не доказывают
результат выбора каждого ресурса. Точные правила поиска соседнего файла .mcmeta отдельно от PNG
остаются открытыми; правила его наследования между паками нельзя считать проверенными.
Пакеты и пути должны проверяться на выход за корень при извлечении. R01 не должен
записывать извлечённые игровые ресурсы в каталоги, отслеживаемые Git.

## 4. Атласы блоков и предметов

Спрайты блоков и предметов нужно учитывать раздельно. При загрузке собрать
зарегистрированные спрайты, выбрать файлы, прочитать изображения и выделить кадры.
Затем разместить кадр каждого спрайта в атласе и выдать координаты UV и ссылку на него.
Не считать исходные PNG готовым общим листом с фиксированными клетками;
не требовать `terrain.png` или `items.png` от паков Minecraft 1.7.10.
Положение спрайта в атласе вычисляется при сборке, не является частью стабильного ID.
После перезагрузки нужно обновить зависимые координаты UV и модели
либо изменить номер поколения ссылок, чтобы старые ссылки больше не использовались.
Анимация меняет содержимое спрайта, не геометрию и не его логический ID.
Физическое объединение GPU-текстур допустимо только при сохранении логического разделения.

Сборка атласа описана в исходниках Forge ветки `1.7.10`:
[TextureStitchEvent.java](https://github.com/MinecraftForge/MinecraftForge/blob/1.7.10/src/main/java/net/minecraftforge/client/event/TextureStitchEvent.java),
blob `6b602e38b520d37aae5fa8c1a931660769cd3490`, и
[TextureMap patch](https://github.com/MinecraftForge/MinecraftForge/blob/1.7.10/patches/minecraft/net/minecraft/client/renderer/texture/TextureMap.java.patch),
blob `75ee568c8eaf0b255fed6f86177722ff1b455b09`.
Прочитаны события до и после сборки атласа, регистрация спрайтов и подключение собственного загрузчика.
Ветка изменяема, хеш объекта Git фиксирует использованную версию файла. Эти исходники описывают API Forge. Они не заменяют проверку работы атласа
в игре и не подтверждают соответствие конкретному JAR из S01.
Исходники/патчи в комплект не копируются.

Журнал сообщает blocks-atlas 512×256 и items-atlas 256×256 для проверенных паков.
Это размеры конкретной сборки атласов, не константы формата.
Координаты UV, отступы между спрайтами, уровни детализации и ограничения видеокарты я не измерял.
Побитовое совпадение упаковки с vanilla не является критерием S05.

## 5. Геометрия и выбор текстур в 1.7.10

В R02 геометрию, спрайт, окрашивание и слой отрисовки нужно выбирать по
идентификатору в реестре, значению metadata, грани и способу отображения.
Если форма зависит от соседних блоков, при выборе нужно учитывать окружение.
Соединения блоков, отсечение невидимых граней и построение сетки относятся к R04.
Для модовых реестров числовой ID нельзя считать постоянным индексом текстуры.

| Класс | Требование к геометрии и материалу |
|---|---|
| Простой полный блок | Куб, выбор спрайтов по граням |
| Блок с разными сторонами | Разные текстуры верха, низа и боковых граней; при необходимости дополнительный слой |
| Растение | Пересекающиеся плоскости, маска прозрачности |
| Ступени/плита | Частичная геометрия; metadata влияет на ориентацию/форму |
| Жидкость | Особая поверхность, текстуры неподвижной и текущей жидкости, окрашивание |
| Обычный предмет | Иконка; отображение в инвентаре и геометрия в руке — разные контексты |
| Особый способ отрисовки | Отдельная реализация; при её отсутствии — заметная модель-заглушка |

Таблица задаёт требования к реализации. Все перечисленные сцены я не проверял.
Внешние современные JSON blockstates/models нельзя считать источником vanilla
геометрии 1.7.10. Ресурс-пак данного опыта заменяет материалы, а не задаёт модель куба.
Особые способы отрисовки, часы, компас, сущности и собственные загрузчики Forge не должны
молча сводиться к универсальному кубу с произвольной текстурой.
Неизвестная модель возвращает отдельную диагностическую модель; неизвестный блок
не превращается в воздух. Это проектное решение, не измеренный vanilla результат.

## 6. Анимации

Размеры изображений и содержимое соседних файлов `.mcmeta`, которые я прочитал из JAR:

| Спрайт | PNG, пиксели | Содержимое animation |
|---|---|---|
| fire_layer_0 | 16×512 | frames: 16…31, 0…15 |
| fire_layer_1 | 16×512 | `{}` |
| lava_flow | 32×512 | frametime: 3 |
| lava_still | 16×320 | frametime: 2; frames: 0…19, 18…1 |
| portal | 16×512 | `{}` |
| water_flow | 32×1024 | `{}` |
| water_still | 16×512 | frametime: 2 |
| clock | 16×1024 | `{}` |
| compass | 16×512 | `{}` |

Для обычной анимации нужно поддержать следующие правила: квадратные кадры шириной PNG, вертикальная лента;
индексы с нуля, последовательность `frames` сохраняет порядок и повторения.
Отсутствующий список — последовательные кадры; отсутствующий frametime — 1 тик.
Поддержать элементы frames как индекс или объект `{index,time}` с длительностью
конкретного кадра; объектные элементы и наследование общего времени проверены визуально.
Значение по умолчанию 1 тик согласуется с совместным опытом повторных индексов
и явного времени; независимого измерения частоты нет. Не включать современную
интерполяцию автоматически. Недопустимые размеры, индексы и длительности диагностировать.

Измерено на собственном apple: PNG 16×32, frames `[0,1]`, frametime 10,
красный и зелёный кадры чередуются в инвентаре. Точная длительность по секундомеру
не измерялась. Это подтверждает работу пути, ленты и соседнего файла .mcmeta, но не все правила парсера.
Часы и компас — особые динамические спрайты: не проигрывать их как обычную
ленту только из-за `{}`. Выбор кадра по миру/игроку нужно описать и проверить отдельно
— в S05 я эти механизмы не проверял.

## 7. Отсутствующие ресурсы и ошибки загрузки

| Условие | Требование | Основание |
|---|---|---|
| Путь отсутствует в пользовательском паке | Поиск ниже до базовых ресурсов | Земля сохранила базовую текстуру |
| PNG найден, но не декодируется | Диагностика и текстурная заглушка; не повторный поиск базового PNG | Сломанный stone дал пурпурно-чёрную клетку в мире и инвентаре |
| Путь отсутствует во всех слоях | Диагностика и текстурная заглушка | Требование к реализации; отдельно не проверял |
| Ошибка метаданных анимации | Диагностика; безопасный текстурная заглушка в Horizon | Vanilla: заглушка при сломанном JSON, индексе 2 из 2 кадров и нулевом времени |
| Неизвестная геометрия | Диагностическая модель, независимо от текстурной заглушки | Проектная политика |

Ошибка одного спрайта не должна обрушать весь клиент Horizon. Диагностика содержит
логический ID, путь и слой-источник, причину; не включает учётные данные и личные пути.
Пурпурно-чёрная заглушка проверена визуально, её точные пиксели не извлекались.
Повреждение PNG нельзя трактовать как простое отсутствие ресурса.

## 8. Дополнительные проверки: анимации, перезагрузка, прозрачность и окрашивание

| Условие | Наблюдение |
|---|---|
| Повреждённый JSON анимации | Заглушка яблока; JsonSyntaxException / EOFException |
| frames=[2] для двух кадров | Заглушка; invalid frameindex 2 |
| Объекты кадров: time=10 и time=40, общий frametime=20 | Зелёный держится примерно в 4 раза дольше красного |
| У зелёного time отсутствует, общий frametime=40 | То же соотношение 4:1 |
| frames отсутствует, frametime=20 | Оба кадра чередуются с равной длительностью |
| frametime отсутствует; десять записей 0 и кадр 1 с time=10 | Видимые длительности равны; согласуется с временем по умолчанию 1 тик и учётом повторений |
| frametime=0 | Заглушка; Invalid default frame time |
| Индивидуальное time=0 | Заглушка; Invalid frame time |

При ошибках анимации голубой камень продолжал отображаться: ошибка одного спрайта
не выключала весь пак. Порядок автоматической последовательности не определён
по моменту старта: проверено циклическое чередование двух кадров.

F3+T после изменения PNG камня в папочном паке дал пурпурный камень вместо жёлтого;
яблоко осталось синим. Состояние до F3+T после записи файла и отдельная проверка
камня в инвентаре не зафиксированы. Перезапись открытого ZIP не является надёжным тестом:
с ней совпали предупреждения чтения pack.mcmeta, причина не установлена.

| Alpha пикселя яблока | Инвентарь | Наблюдавшийся вид в руке |
|---|---|---|
| 0 | Невидим | Невидим |
| 128 | Полупрозрачный красный | Визуально непрозрачный красный |
| 255 | Непрозрачный красный | Непрозрачный красный |

В R02 нужно учитывать способ отображения предмета. Точный порог отсечения по alpha,
настройки смешивания цветов, вид от третьего лица и поведение других предметов не установлены.
Первый опыт alpha=128 был недействителен: журнал показал активный пак с alpha=0.
Таблица основана на повторном опыте после смены пака.

Белые stone и grass_top дали белый камень и зелёный верх травы. После подмены
colormap/grass.png сплошной красной картой 256×256 верх стал красным; боковая
травяная часть сохранила рисунок, но стала красной; земля и камень сохранили цвет.
На скриншоте высокая трава также красная. Это согласуется с умножением на цвет окрашивания,
но не доказывает точную формулу умножения, координаты выборки или зависимость от биома.
Для R02 спрайт, цвет окрашивания и слой боковой грани должны представляться раздельно;
вывод о внутреннем числе команд отрисовки из скриншота не делается.

## 9. Файлы и повторение проверок

`tools/probe_s05.py` читает метаданные локального JAR без извлечения/публикации
изображений. Команда packs создаёт два базовых пака, extended — дополнительные
паки для остальных опытов. Все изображения для этих паков создаются программно.
Используется Python 3.10+, сторонние пакеты не нужны.
Команды PowerShell из корня репозитория, каждая одной строкой:

```powershell
python tools/probe_s05.py inspect --jar "$env:USERPROFILE\Documents\horizon-reference\versions\1.7.10\1.7.10.jar"
```

```powershell
python tools/probe_s05.py packs --output ".local/s05-packs"
```

Паки скопировать в `resourcepacks` эталонной установки; включать по одному,
кроме явно обозначенных опытов со стеком.
Генератор отказывается перезаписывать существующие файлы. ZIP не требуется коммитить:
в репозитории остаётся скрипт генерации. Во время опытов я использовал отдельные
команды Python. Итоговый скрипт проверен на созданных для тестов данных,
но паки из него я повторно в Minecraft не запускал.

```powershell
python -m unittest discover -s tests -p "test_probe_s05.py" -v
```

Rust-код не меняется. Корневой Cargo.toml в чтении GitHub вернул 404;
upstream SHA и наличие `crates/horizon-assets/` не подтверждены.
Документ не фиксирует существующие Rust API и не объявляет `cargo`-проверки успешными.

В комплект входят описание имён ресурсов, атласов, моделей и обработки ошибок,
скрипт генерации тестовых паков и мой отчёт. Полнота относительно текущего текста #18 требует проверки. CI и проверка изменений остаются обязательными шагами перед принятием PR.
Полную поддержку всех способов отрисовки, ресурс-паков и Forge ещё нужно реализовать и проверить.

Команды для остальных опытов и таблица проверок: [S05-reproduce](../reports/S05-reproduce.md).
