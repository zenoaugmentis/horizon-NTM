# S02 — контракт блоков: LegacyBlockId, metadata, модовые реестры

**Issue:** #15 (`S02`) · **Зависит от:** S01 (#14, PR #107) · **Потребители:** S08, S10, W01, W02, W04, R04, N03, X01
**Статус:** предложение на review. Пункты **⚠** проверяются на эталонных мирах (S06) до реализации W01.

Эталонная модель: [`tools/legacy_blocks.py`](../../tools/legacy_blocks.py), тест-векторы:
[`tests/test_legacy_blocks.py`](../../tests/test_legacy_blocks.py). Реализация W01/W02 на Rust обязана
проходить те же векторы.

## 1. Внешняя модель 1.7.10 (диск и сеть)

| Понятие | Тип | Диапазон | Где встречается |
|---|---|---|---|
| `LegacyBlockId` | `u16` | `0..=4095` (12 бит) | Anvil: байт `Blocks` (младшие 8 бит) + нибл `Add` (старшие 4); сеть: id в пакетах |
| `LegacyMeta` | `u8` | `0..=15` (4 бита) | Anvil: нибл `Data`; сеть: meta в пакетах |
| `LegacyBlock` | `{ id, meta }` | 65 536 пар | везде, где 1.7.10 говорит «блок» |
| `packed` | `u16 = id << 4 \| meta` | `0..=0xFFFF` | внутренний ключ. Совпадает с ключом vanilla 1.12 `blockId << 4 \| data` в таблице Horizon `block_state_data.txt` |
| `BlockName` | строка `namespace:path` | — | реестр FML: `minecraft:stone`, `<modid>:<name>` |

Правила:

- Ванильные блоки 1.7.10 имеют **фиксированные** id `0..=175` (175 — `minecraft:double_plant`).
  Номера 165–169 в 1.7.10 не заняты: в 1.8 там появились slime, barrier, iron_trapdoor, prismarine, sea_lantern.
- Числовой id модового блока — **свойство мира**, а не мода: один и тот же блок в двух мирах может
  иметь разные номера. Устойчивая идентичность — только `BlockName`.
- Карту `name ↔ id` мира хранит FML в `level.dat`. ⚠ Формат (компаунд `FML`, список `ItemData`
  с парами `K`/`V`; у блоков к имени добавлен префикс `\u0001`, у предметов — `\u0002`) специфицируется
  в S03/W06 и проверяется на эталонном мире Forge 10.13.4.1614.

## 2. Внутренняя модель (граница с Horizon)

Horizon хранит блоки как `BlockStateId(u32)` — индекс в `BlockRegistry`. Состояние — это имя и
свойства (`horizon-world/src/registry.rs`, `chunk.rs`). Палитры секций, meshing, рендер и сеть
работают с `BlockStateId`. Реестр уже рассчитан на модовые блоки (~190 000 состояний).

**Решение:** внутренняя модель остаётся `BlockStateId`. `LegacyBlock` используется **только на
границах**: загрузка и сохранение чанка, сетевой кодек, API модов. `id/meta` не становится внутренней
моделью Horizon — это требование `TEAM_ROADMAP.md`, раздел 6.

Профиль 1.7.10 строит реестр так:

1. Каждому `BlockName` из карты мира соответствует **один блок с одним свойством `meta`** со значениями
   `"0"…"15"`. В Horizon это `BlockState { name: "minecraft:wool", properties: {meta: "14"} }`.
2. Регистрируются **все 16 значений meta** у каждого блока, даже если 1.7.10 использует меньше.
   Так преобразование `LegacyBlock ↔ BlockStateId` становится биекцией и не теряет данные.
   Пример: `stone:1` в 1.7.10 рисуется как обычный камень, а в 1.12 это уже гранит.
   Вид такого состояния определяет описание блока (§4), а не реестр.
3. Состояния одного блока идут подряд, поэтому
   `BlockStateId = base(name) + meta` и `meta = id − base(name)`. Обе операции O(1), без хэш-таблиц.
4. Предел: 4 096 имён × 16 = 65 536 состояний. Это меньше, чем Horizon держит сейчас.

```text
диск/сеть                         граница (W01/W02)                        движок Horizon
LegacyBlock{35,14} ──packed 574──▶ BlockIdMap: 35 → "minecraft:wool" ──▶ BlockStateId(base(wool)+14)
                                   ◀── id(name), meta = state − base ◀──
```

## 3. Неизвестные и отсутствующие блоки

Цель: **никогда не терять блоки молча**, даже если мод удалён.

| Ситуация | Что делаем | Что сохраняем обратно |
|---|---|---|
| id есть в карте мира, мод загружен | обычный блок | тот же id/meta |
| id есть в карте мира, мода **нет** (`missing`) | блок с исходным именем (`gonemod:pipe`), помечен missing: без поведения, рисуется заглушкой | тот же id/meta, запись в карте сохраняется |
| id нет ни в карте, ни среди ванильных | синтетическое имя `horizon_ntm:unknown_<id>`, missing | тот же id/meta; в карту мира **не** добавляется |
| мод регистрирует блок, которого нет в карте | `allocate`: наименьший свободный id `≥ 176` | новая запись в карте мира |
| мир требует id, занятый другим именем | **ошибка загрузки**, мир не открывается | — |
| свободных id не осталось (4 096) | ошибка регистрации мода | — |

TileEntity у missing-блоков хранится как необработанный NBT и записывается обратно без изменений (W11).
⚠ Политика выделения «наименьший свободный ≥ 176» — **наша**. Её совпадение с FML не утверждается.
Для открытия наших миров настоящим Forge это не важно: FML читает карту из `level.dat`.

## 4. Описание блока: что знает реестр, а что — определение блока

Реестр знает только имя и meta. Значение meta (цвет, направление, верхняя/нижняя половина) задаёт
**определение блока**: таблица для ванили (W01/W02) или регистрация модом (S10/X01):

```text
BlockDef {
  name:        "minecraft:wool",
  used_metas:  0..=15,          // какие meta 1.7.10 реально ставит; остальные ведут себя как meta_fallback
  meta_fallback: 0,
  // поведение, коллизии, свет, звук, модель — по meta (задачи G*, R*)
}
```

### Мост к моделям Horizon (только рендер ванили)

Чтобы переиспользовать модели и текстуры Horizon для ванильных блоков (R02/R04), вводится
`modern_view(LegacyBlock) -> Option<BlockState>`. Она построена на таблице 1.12→1.13
`horizon-world/src/datafix/block_state_data.txt`, ключ — тот же `packed`.

Проверено по таблице:

| 1.7.10 | packed | 1.13-состояние из таблицы | Верно для 1.7.10? |
|---|---|---|---|
| `wool:14` | 574 | `minecraft:red_wool` | да |
| `stone:0` | 16 | `minecraft:stone` | да |
| `stone:1` | 17 | `minecraft:granite` | **нет**: гранита в 1.7.10 нет, нужно `minecraft:stone` |
| `dirt:2` | 50 | `minecraft:podzol` | да (podzol есть с 1.7.2) |
| `dirt:1` | 49 | `minecraft:coarse_dirt` | ⚠ coarse dirt появился в 1.8; что meta 1 значит в 1.7.10, проверить |
| `coal_block:0` / `packed_ice:0` | 2768 / 2784 | `coal_block` / `packed_ice` | да (ids 173/174 совпадают) |
| `double_plant:0` | 2800 | `sunflower[half=lower]` | да |
| `melon_block:1` | 1649 | записи нет | таблица отдаёт состояние блока по умолчанию; так и нужно |

Правила `modern_view`:

- работает только для `minecraft:*` и только для рендера и моделей; **поведение** берётся из определения блока 1.7.10;
- блоки и значения meta, появившиеся в 1.8–1.12, перекрываются таблицей исключений `legacy_1710_overrides`
  (W02). Известны: варианты камня (meta 1–6), мокрая губка (`sponge:1`), coarse dirt (⚠). Полный список
  W02 строит сравнением с эталонными мирами S06;
- для модовых блоков возвращает `None`: модели модов идут своим путём (R*/X07).

⚠ Лицензия: `block_state_data.txt` по словам Horizon сгенерирован из кода vanilla (см. `docs/LEGAL.md`, §5).
Использовать как часть импортированного кода Horizon допустимо по его MIT. Если ревью решит иначе,
W02 строит `modern_view` по наблюдениям и тест-векторам без этой таблицы.

## 5. Граница с предметами (детали — S08)

- `ItemBlock` использует id своего блока (`0..=4095`); ванильные предметы — `256..`.
- ⚠ Модовые предметы FML 1.7.10 выделяет выше 4095 (до 31999). Диапазон подтверждается в S08 на эталонном мире.
- Стек хранит `id: i16` и `Damage: i16`. Для блочных предметов damage обычно равен meta блока, но
  связь задаёт определение предмета, а не этот контракт.

## 6. Примеры преобразований

| Вход | Шаги | Результат |
|---|---|---|
| Anvil: `Blocks=0xD0`, `Add=0x7`, `Data=7` | id = `0x7 << 8 \| 0xD0` = 2000; карта мира: 2000 → `examplemod:ore` | `BlockStateId(base(examplemod:ore) + 7)` |
| `LegacyBlock{35,14}` | packed 574; 35 → `minecraft:wool` | `minecraft:wool[meta=14]`; `modern_view` → `red_wool` |
| `LegacyBlock{300,5}`, мода `gonemod` нет | карта: 300 → `gonemod:pipe` (missing) | `gonemod:pipe[meta=5]`, сохраняется как `{300,5}` |
| `LegacyBlock{1234,9}`, id не в карте | синтетическое имя | `horizon_ntm:unknown_1234[meta=9]` → обратно `{1234,9}` |
| мод регистрирует `examplemod:machine` в мире без него | `allocate` | id 176 (если свободен) |

## 7. Что меняется в коде Horizon (для W01/W02, не в этой задаче)

- `horizon-core` или `horizon-items`: типы `LegacyBlockId`, `LegacyMeta`, `LegacyBlock`, `BlockName`.
- `horizon-world`: `BlockIdMap` (per-world), построение `BlockRegistry` для профиля 1.7.10, `base(name)`.
- Профиль 26.3 не трогается: новые типы живут рядом, переключение — через `VersionProfile` (план аудита, этап 2).
