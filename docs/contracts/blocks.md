## 1. Модель 1.7.10

| Понятие | Диапазон | Где живёт |
|---|---|---|
| block id | `0..=4095` (12 бит) | секция Anvil: `Blocks` (младшие 8 бит) + `Add` (старшие 4) |
| metadata | `0..=15` (4 бита) | секция Anvil: `Data` |
| item id | `0..=31999` | **то же** числовое пространство, что у блоков |
| имя | `modid:name`, ваниль — `minecraft:…` | `level.dat` → `FML` → `ItemData` |

```rust
// Публичный тип W01. Без проверки диапазонов не создаётся.
pub struct LegacyBlock { id: u16 /* 0..=4095 */, meta: u8 /* 0..=15 */ }
```

**Упаковка:** `packed = id << 4 | meta`, `u16`, все 65 536 значений допустимы и взаимно однозначны.
Тот же порядок бит — в ключах datafix 1.12 Horizon и в записях Multi Block Change протокола 5 (S04).

**Anvil** (секции целиком — S03): `Blocks[i] = id & 0xFF`; `Add` пишется, только если
в секции есть `id > 255`, и хранит `id >> 8`; `Data` хранит `meta`. Ниббл с чётным индексом —
младшие 4 бита байта, с нечётным — старшие. Прочитанные биты сохраняются как есть,
включая ненулевую `meta` у air.

**Ваниль 1.7.10:**
- блоки `0..=175`, кроме `165..=169` (их займёт 1.8);
- предметы `256..=422` и пластинки `2256..=2267`.

Точные списки «имя ↔ id» берутся из `ItemData` свежего Forge-мира 1.7.10 (фикстура S06),
не из Minecraft Wiki. До S06 — подмножество в тестах; остальное `UNKNOWN`.

## 2. Пространство id и реестр мира

Блоки и предметы делят **одно** пространство `0..=31999` (FML `availabilityMap`):
один id занят либо блоком, либо предметом. Исключение — `ItemBlock`: предмет блока
имеет **то же имя и тот же id**, что и блок.

`LegacyRegistry` мира содержит:

| Поле | Содержимое | `level.dat` → `FML` |
|---|---|---|
| blocks | `name ↔ id`, `id <= 4095` | `ItemData`: `{K: "\u0001" + name, V: id}` |
| items | `name ↔ id` | `ItemData`: `{K: "\u0002" + name, V: id}` |
| blocked | id, которые нельзя выдавать | `BlockedItemIds` (int array) |
| aliases | `старое имя → новое` для блоков и предметов | `BlockAliases`, `ItemAliases`: `{K, V}` |
| substitutions | имена с подменой | `BlockSubstitutions`, `ItemSubstitutions`: `{K}` |
| mods | `ModId`, `ModVersion` | `ModList` |

Все поля читаются и **записываются обратно**, даже если мы их ещё не используем.
Старый формат FML `ModItemData` (до 1.7) не поддерживается: мир с ним — ошибка загрузки
с понятным сообщением.

### Выдача id (как FML 1.7.10, бит в бит)

- Блок: подсказанный id, если он свободен и `<= 4095`, иначе **первый свободный от 0**.
  В ванильном 1.7.10 первый блок мода получает **165**.
- `ItemBlock`: id своего блока.
- Предмет: подсказанный id, если он свободен, иначе **первый свободный от 4096**
  (так ваниль получает свои фиксированные id, а моды — 4096+).
- «Свободный» = не занят блоком, предметом и не в `blocked`.
- Больше 4095 блоков — ошибка регистрации.

Совпадение с FML обязательно: Forge-серверы и миры, созданные Forge, должны давать
те же id, что и Horizon.

### Правила

- Имя обязано иметь namespace (`modid:name`).
- Конфликт — ошибка загрузки, а не тихая перезапись: одно имя с двумя id; один id у двух
  разных имён; блок и предмет с одним id, но разными именами.
- Мир без `FML` — ванильный: реестр = ванильная таблица.

## 3. Жизненный цикл (динамические реестры)

```
регистрация модов → freeze → [загрузка мира → игра → сохранение → выгрузка]* 
                                   ↑ клиент: карта сервера из handshake
```

1. **Регистрация** (S10): ваниль, затем моды в порядке загрузки. Каждая регистрация
   выдаёт id по правилам раздела 2. После этого реестр **заморожен** (`frozen`):
   новые имена в рантайме запрещены.
2. **Загрузка мира** (сервер и одиночная игра) — порядок как у `GameData.injectWorldIDMap`:
   1. занять `blocked`, применить алиасы, затем substitutions;
   2. сначала все блоки, потом все предметы (чтобы `ItemBlock` встал на id блока):
      каждое имя из мира получает **id из мира**, даже если `frozen` выдал другой;
   3. имя из мира, которого нет в `frozen` (мод удалён), — **missing**: id остаётся за ним,
      запись остаётся в `ItemData`. *Отличие от FML:* FML после подтверждения игрока
      освобождает такие id; мы — нет, чтобы мод можно было вернуть без потерь;
   4. имена из `frozen`, которых нет в мире (мод добавлен), получают id по правилам
      раздела 2, не задевая id мира, missing и `blocked`.
   Перенумерации чанков не требуется: внутренний id зависит только от legacy id (раздел 4).
3. **Сохранение:** весь `FML` пишется обратно (раздел 2), `ModList` — по загруженным модам,
   missing-записи сохраняются.
4. **Выгрузка мира:** реестр возвращается к `frozen`.
5. **Клиент в сети:** карта приходит от сервера в FML handshake `ModIdData`
   (`name → VarInt id`, плюс substitutions) **до** перехода в play и полностью заменяет
   клиентскую. Клиент id никогда не выдаёт; неизвестные ему имена — missing.
   Пир без FML handshake получает только ванильные id; политика подмены модовых
   блоков для него — S04/N05.

## 4. Внутренняя модель: граница с Horizon

Horizon хранит блоки как плотный `BlockStateId(u32)`; у блока непрерывный диапазон
`base..base+count` (`StateTable`, `BlockInfo { base, count }`); реестр строится из выгрузки
данных (`BlockRegistry::from_facts_json` / `from_nbt`); имена в `StateTable` уникальны (`by_name`).

Контракт:

1. Legacy-реестр Horizon — **плотный и фиксированный**: ровно 4096 блоков, у каждого
   одно свойство `meta` на 16 значений (`"0"`..`"15"`), всего 65 536 состояний.
2. `BlockStateId = id << 4 | meta` = `packed`; `base(id) = 16 × id`. Обе стороны O(1),
   без таблиц, и id **не зависит** от того, что было загружено раньше.
3. Имя блока в Horizon для id:
   - зарегистрированный загруженный — его имя;
   - missing (мод не загружен) — его исходное имя, флаг `missing`;
   - свободный id — `horizon:unknown_<id>`.
   Все имена уникальны.
4. Смысл meta (направление, возраст, цвет, половина) — **не** часть состояния.
   Его читают функции поведения блока (W02, G-задачи) и модов (S10).
   Поэтому для W01 не нужна полная таблица свойств 1.7.10.
5. Палитры секций Horizon (`PalettedContainer`) хранят этот `BlockStateId`; ширина глобальной
   палитры — 16 бит. Локальные палитры (до 8 бит) работают как в 26.3.
6. Реестр 26.3 и legacy-реестр **не смешиваются** в одном мире; переключатель — версия мира (W03).

## 5. Unknown и missing

| Ситуация | Поведение |
|---|---|
| id в чанке, в реестре свободен | `horizon:unknown_<id>`; id и meta сохраняются |
| имя в мире, мод не загружен | missing с исходным именем; id не освобождается и не выдаётся другим |
| сохранение | исходные `id`/`meta` в чанке и записи `ItemData` — без изменений |
| игрок ломает unknown/missing | разрешено, дроп пустой; ставить их нельзя |

Forge 1.7.10 в этой ситуации предлагает удалить блоки — мы **никогда** не теряем данные молча.

## 6. Граница с предметами

- `0..=4095`: блок (и его `ItemBlock` с тем же id) **или** обычный предмет (ваниль `256..=422`,
  `2256..=2267`). Модовые предметы туда не попадают — их id с 4096.
- `4096..=31999`: только предметы.
- `item damage` → meta для `ItemBlock` — функция конкретного блока, а не всегда `damage & 15`.
  Модель `ItemStack` — S08.

## 7. `modern_view` — только для рендера

До готовности R02 разрешён адаптер `LegacyBlock → состояние 26.3`, чтобы брать
современные модели Horizon:

1. ключ `id << 4 | meta` → таблица Horizon `block_state_data.txt` (1.12 → 1.13) → 26.3;
2. раньше таблицы применяются **исключения 1.7.10**:

| 1.7.10 | В 1.12 | `modern_view` |
|---|---|---|
| `stone` meta `1..=15` | granite, diorite, andesite… (1.8) | `minecraft:stone` |
| id `165..=169` | slime, barrier, iron_trapdoor, prismarine, sea_lantern | исходное имя, если это мод; иначе `unknown` |
| ванильный id `> 175` | блоки 1.8+ | `unknown` |
| блок мода | — | его имя (модель — от мода) |

Список неполный: каждое найденное расхождение добавляется сюда и в векторы.
`modern_view` **никогда** не используется для сохранения, сети и логики.

## 8. Примеры преобразований

| Вход | Результат |
|---|---|
| `minecraft:wool`, id 35, meta 14 (красная) | `packed = BlockStateId = 574`; Anvil `Blocks 35, Add 0, Data 14` |
| `ntm:ore_uranium`, id 1204, meta 0 | `packed = 19264`; Anvil `Blocks 180, Add 4, Data 0` |
| первый блок мода в ванильном мире | id `165` |
| первый предмет мода | id `4096` |
| `ItemBlock` блока 165 | предмет с id `165` и тем же именем |
| мир: `ntm:ore → 1204`; `frozen` выдал 170 | в этом мире блок имеет id 1204 |
| мир: `oldmod:x → 300`, мод удалён | missing `oldmod:x`, id 300 занят, запись сохраняется |
| id 2000 в чанке, нигде не зарегистрирован | `horizon:unknown_2000`, сохраняется как 2000 |
| `stone` meta 3 в `modern_view` | `minecraft:stone` (не diorite) |
