# S02 · Контракт LegacyBlock: id/metadata, имена модов, unknown ID, граница с Horizon

Статус: контракт S02 (#15), зависит от S01 (`docs/specs/versions.md`). Дата: 2026-11-08.
Потребители: W01, W02 (M2), S03, S04, S08, S10, R04.

Upstream Horizon, по которому проверена граница: `horizon-rust/horizon@447e9d277d06272196ba66363d5ea8d582581c63`
(`crates/horizon-world/src/registry.rs`, `level/states.rs`, `datafix/block_state_data.*`).

Исполняемый эталон: `tools/legacy_blocks.py`. Тестовые векторы: `tests/test_legacy_blocks.py` —

## 1. Модель 1.7.10

| Понятие | Диапазон | Где живёт в 1.7.10 |
|---|---|---|
| block id | `0..=4095` (12 бит) | секция чанка: `Blocks` (младшие 8 бит) + `Add` (старшие 4 бита) |
| metadata | `0..=15` (4 бита) | секция чанка: `Data` (nibble на блок) |
| block name | `modid:name`, ваниль — `minecraft:…` | FML-реестр мира в `level.dat` |
| item id | `0..=31999` | тот же числовой ряд; у `ItemBlock` id = id блока |

```rust
// Публичный тип W01. Значение без инвариантов не создаётся.
pub struct LegacyBlock { id: u16 /* 0..=4095 */, meta: u8 /* 0..=15 */ }
```

**Упаковка.** `packed = id << 4 | meta`, `u16`, все 65 536 значений допустимы и взаимно однозначны.
Тот же порядок бит — в ключах datafix 1.12 Horizon и в записях Multi Block Change протокола 5 (S04).

**Хранение в Anvil** (детали секций — S03):
`Blocks[i] = id & 0xFF`; `Add` нужен, только если в секции есть `id > 255`, и хранит `id >> 8`;
`Data` хранит `meta`. Ниббл с чётным индексом — младшие 4 бита байта, нечётный — старшие.

**Ваниль 1.7.10** занимает id `0..=175`; `165..=169` в 1.7.10 **не заняты** (их займёт 1.8).
Ванильные id фиксированы: мир без FML-данных читается по ванильной таблице.

`0` — всегда `minecraft:air`. Ненулевая `meta` у air при чтении сохраняется как есть,
как и любые другие прочитанные биты (раздел 4).

## 2. Имена и реестр мира

У каждого мира свой `BlockIdMap`: взаимно однозначное соответствие `name ↔ id`.

- Источник для миров Forge — `level.dat` → `FML` → `ItemData`: список `{K: string, V: int}`,
  где `K` начинается с `\u0001` для блоков и `\u0002` для предметов
  (`"\u0001minecraft:stone" → 1`). Остальные поля `FML` (`BlockAliases`, `ItemAliases`,
  `BlockedItemIds`, substitutions) читаются и **сохраняются без изменений**, даже если мы
  их ещё не понимаем. Точная форма подтверждается фикстурой S06; до этого — `UNKNOWN`
  для всего, кроме `ItemData`.
- Мир без `FML` — ванильный: карта = ванильная таблица 1.7.10.
- **Мир главнее кода.** Если мир говорит `ntm:ore_uranium → 1204`, блок получает 1204,
  что бы ни выбрал загрузчик модов.
- Новые имена (мод добавлен в существующий мир или новый мир) получают **наименьший
  свободный id `>= 256`**. Ваниль `0..=255` и её дыры (`165..=169`) модам не раздаются:
  это наша политика, она не повторяет аллокатор FML и описана здесь, чтобы её никто не «чинил».
- Имя обязано иметь namespace (`modid:name`), иначе ошибка регистрации.
- Конфликт (одно имя — два id, или один id — два имени) — ошибка загрузки мира,
  а не тихая перезапись.

## 3. Внутренняя модель: граница с Horizon

Horizon хранит блоки как плотный `BlockStateId(u32)`; у каждого блока непрерывный
диапазон `base..base+count` (`StateTable`, `BlockInfo { base, count }`), реестр строится
из выгрузки данных (`BlockRegistry::from_facts_json` / `from_nbt`), а не из кода.

Контракт:

1. При загрузке мира строится **legacy-реестр** из `BlockIdMap`: каждому id в порядке
   возрастания — блок Horizon с **одним** свойством `meta` на 16 значений (`"0"`..`"15"`).
   Все 16 состояний существуют, даже если ванильный блок использует меньше: это делает
   преобразование без потерь.
2. `BlockStateId = base(id) + meta`; обратно — `block(state)` и `state - base`. Обе стороны O(1).
3. Смысл meta (направление, возраст, цвет, верхняя половина) — **не** часть состояния.
   Его читают функции поведения конкретного блока (W02, G-задачи) и модов (S10).
   Поэтому для W01 не нужна полная таблица свойств 1.7.10.
4. Палитры секций Horizon (`PalettedContainer`) хранят этот `BlockStateId`; ширина
   глобальной палитры = `ceil(log2(16 × блоков в реестре))`.
5. Современный 26.3-реестр Horizon и legacy-реестр **не смешиваются** в одном мире.
   Переключатель — версия мира (W03).

## 4. Unknown и missing

| Ситуация | Поведение |
|---|---|
| id есть в чанке, нет в `BlockIdMap` | плейсхолдер `horizon:unknown_<id>`, 16 состояний, id и meta сохраняются |
| имя есть в `BlockIdMap`, мод не загружен | плейсхолдер `horizon:missing` с исходным именем; id не освобождается |
| сохранение мира с плейсхолдерами | исходные `id`/`meta` и запись `ItemData` записываются обратно байт в байт |
| игрок ломает плейсхолдер | разрешено, дроп пустой; ставить плейсхолдеры нельзя |

Forge 1.7.10 в такой ситуации предлагает удалить блоки — мы **никогда** не теряем данные
молча. Плейсхолдер рисуется отдельной текстурой (R-задачи).

## 5. Граница с предметами

- id `0..=4095` — блоки; у блока может быть `ItemBlock` с тем же id.
- id `4096..=31999` — только предметы. `item damage` для `ItemBlock` превращается в meta
  функцией конкретного блока, а не `damage & 15` всегда. Полная модель `ItemStack` — S08.
- Предметы — отдельный реестр (`\u0002`), тот же числовой ряд: id блока и предмета
  не может принадлежать двум разным именам.

## 6. `modern_view` — только для рендера

Чтобы использовать модели/текстуры современного пути Horizon до готовности R02,
разрешён адаптер `LegacyBlock → состояние 26.3`:

1. ключ `id << 4 | meta` → таблица Horizon `block_state_data.txt` (1.12 → 1.13) → 26.3;
2. перед таблицей применяются **исключения 1.7.10**:

| 1.7.10 | В 1.12 | `modern_view` |
|---|---|---|
| `stone` meta `1..=15` | granite, diorite, andesite… (1.8) | `minecraft:stone` |
| id `165..=169` | slime, barrier, iron_trapdoor, prismarine, sea_lantern | плейсхолдер `unknown` |
| id `> 175` без мода | блоки 1.8+ | плейсхолдер `unknown` |

Список не полный: каждое новое расхождение добавляется сюда и в тестовые векторы.
`modern_view` **никогда** не используется для сохранения, сети и логики — только рендер.

## 7. Примеры преобразований

| Вход | Результат |
|---|---|
| `minecraft:wool`, id 35, meta 14 (красная) | `packed = 574`, `Blocks = 35`, `Add = 0`, `Data = 14` |
| `ntm:ore_uranium`, id 1204, meta 0 | `packed = 19264`, `Blocks = 180`, `Add = 4`, `Data = 0` |
| legacy-реестр `{0 air, 1 stone, 35 wool}`, wool meta 14 | `BlockStateId = 2·16 + 14 = 46` |
| id 2000 в чанке, нет в карте | `horizon:unknown_2000`, сохраняется как 2000 |
| `stone` meta 3 в `modern_view` | `minecraft:stone` (не diorite) |
